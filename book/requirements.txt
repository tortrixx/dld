# ============================================================================
#  book/requirements.txt —— 站点的 Python 依赖（锁到具体版本）
# ----------------------------------------------------------------------------
#  为什么锁版本：这个站点要能被**任何一台机器**一条命令重建出来。
#  只写 `mkdocs-material` 会让半年后的构建装到别的版本而行为不同
#  （例如某个配置键被改名），而这份文档是要交课程、要给答辩现场用的，
#  不允许"昨天能构建、今天不能"。
#
#  使用（在仓库根目录）：
#      python -m venv book/.venv                  # Windows
#      book/.venv/Scripts/python -m pip install -r book/requirements.txt
#      python book/scripts/book.py serve          # 一条命令：生成 + 起本地服务
#
#  ⚠️ 这里**必须列全** `mkdocs.yml` 的 `plugins:` 里用到的每一个插件。
#     2026-10-15 第 27 工作阶段踩过一次：`glightbox` 只在本地 pip 装过、**没写进
#     本文件**，于是 CI 的 `mkdocs build` 直接报
#     `Config value 'plugins': The "glightbox" plugin is not installed` ——
#     而本地一切正常。**"本地能构建"不等于"requirements 是完整的"**，
#     验证方法见文件末尾。
#
#  版本是 2026-10-15 在 Python 3.14.6（本机）与 3.12（CI）上实际安装并构建通过的。
# ============================================================================

mkdocs==1.6.1
mkdocs-material==9.7.7
# 图片点击放大（灯箱）。Material 9.7.x 起**不再自带** glightbox 插件，
# 必须单独装；`mkdocs.yml` 的 `plugins: - glightbox` 依赖它。
mkdocs-glightbox==0.5.2
selectolax==1.0.0
pymdown-extensions==12.3
# 中文站内搜索需要分词：Material 的 search 插件在语言含 zh 时 import jieba。
# 没装也不报错，但搜索会把整句中文当成一个词 ⇒ "搜得到"变成"搜不到"。
jieba==0.42.1

# ----------------------------------------------------------------------------
#  怎么验证"本文件是完整的"（不要靠"我本地能构建"）
# ----------------------------------------------------------------------------
#  在一个**全新的**虚拟环境里按本文件安装，然后构建一次：
#
#      python -m venv /tmp/book-ci
#      /tmp/book-ci/bin/python -m pip install -r book/requirements.txt
#      /tmp/book-ci/bin/python -m mkdocs build --strict -f book/mkdocs.yml \
#          --site-dir /tmp/book-ci-out
#
#  只要 `mkdocs.yml` 里引用了没列在这里的东西（插件、`!!python/...` 模块），
#  这一步就会以"configuration error"失败 —— 那正是 CI 会遇到的失败。
