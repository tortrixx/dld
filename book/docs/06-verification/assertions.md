## 二、关键断言逐条讲解

命名约定：`①②③…` 是主断言；带字母的（`⑤b`/`⑥c`/`⑦b`/`⑧b`/`⑪b`）是**同一场景下的补充判据**
（补的是"容易漏掉的那一半"，例如早采样点的鬼影、被包含关系压过的消隐）。

!!! quote "⑳ 这条断言为什么值得单独写"
    竞态类缺陷的特点是**平时不出现**：只有在"移动/旋转的同一拍正好构成整帧"时才会误判，
    手玩几乎碰不到，但一旦碰到就是"拼好了却提示失败"。所以判据不能只写"能拼成"，
    而要写**"在每一个提交拍之后的窗口里，不允许出现基于旧判据的成功"** ——
    这条断言把"竞态不存在"变成了可数的事实。

## 三、两条最容易被忽略的判据（原文）

**`puzzle_ctrl` ⑳ —— 主路径竞态保护**

> 提交拍 97 个（`pos_cnt` 变化 / `o_pos` / `o_ori` 变化）、帧尾拍 330 个；
> 逐提交窗口 `[提交拍, 下一次帧尾拍)` 共 **18 763** 个采样拍，其中 `frm_valid=1`（陈旧判据仍然有效）
> **15 746** 个 —— 窗口真实存在；**`o_all_lock=1` 的采样 0 次误判**。

**`puzzle_top` ① —— 自检画面（要求**同时**出现 `0x7F` 与 `0x00`）**

> 采样 141 个：全黄 75、全灭 66、其它 0；8 位数码管**都出现过** `'8'` = True；
> **都出现过消隐 `0x00`** = True（未见消隐的位槽 = 无）；各位槽段码集合 = `{0: [' ','8'], …}`。

第二条的关键在于**"同时"**：只查"出现过 8"会放过"位选一直停在同一位"的缺陷；
只查"出现过灭"会放过"根本没点亮"的缺陷。两条都出现，才说明**扫描真的扫遍了 8 个位槽**。
