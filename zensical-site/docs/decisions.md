# 工程取舍

工程结果既包括实现了什么，也包括为什么保留限制。以下决策以现有 RTL、测试和历史工程记录为依据。

## 固定初始朝向，保留旋转的必要性

开局位置随机，初始朝向使用 `PIECE_ORI_INIT` 固定值。玩家仍可原地旋转 90°，但项目没有实现“初始方向随机”。固定朝向用于保证旋转是解题必需的一步。

[几何检查](https://github.com/tortrixx/dld/blob/main/scripts/check_geometry.py)与[走法检查](https://github.com/tortrixx/dld/blob/main/scripts/check_plans.py)可离线验证这项选择；它们不能代替 RTL 仿真或上板。

## 按覆盖画面判定，不绑定零片身份

每行覆盖掩码与目标行一致，并且全部零片锁定，才输出成功。这样形状相同的零片交换身份也不会被误判。

[引擎测试台](https://github.com/tortrixx/dld/blob/main/sim/tb_puzzle_ctrl.py)包含等价铺法场景；相关历史问题为 ERR-021。旋转越界时不提交新朝向，碰撞检查通过才提交候选位置。

## 只在散落握手完成后判决

刚进入对局时，引擎可能还保留上一局的锁定状态。`shuf_seen` 记录本局已经观察到散落忙信号，避免把旧结果当作新一局的胜负。

具体逻辑见[状态机源码](https://github.com/tortrixx/dld/blob/main/rtl/game_fsm.vhd)，验证入口见[游戏主控](modules/03_game_fsm.md)。

## 在资源上限前停止增加音效

被拒绝的移动或旋转没有提示音。历史试验新增逻辑后超过 LAB 容量，因此回退；不能在展示中将其写成完整交互反馈。

记录见[资源优化过程](https://github.com/tortrixx/dld/blob/main/docs/05-资源利用与编译报告.md)。音效仿真能验证码表与方波，听感需要硬件确认。

## 保留已知边界

- 散落达到重试上限后，极端回退分支未做完整重叠检查（ERR-018b）。不宣称随机散落在所有输入下都无重叠，也不为其给出未经严谨验证的概率。
- “干净帧”快照窗口存在已记录的时序边界（ERR-041），需要针对性复测。
- 仿真截图使用压缩时间；图上的毫秒数不能直接当作真实游戏时长。
- 仓库没有硬件实拍；网站演示明确标为软件模型。

这些限制保留在[硬件调试记录](https://github.com/tortrixx/dld/blob/main/docs/06-硬件调试记录.md)，公开站仅摘录工程结论，不发布课程材料与内部工作日志。
