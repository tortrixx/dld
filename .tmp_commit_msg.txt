fix(27 工作阶段): requirements.txt 补上 mkdocs-glightbox —— 这是 CI 构建失败的根因

现象：第一次 CI 运行（commit 1d6f384）里 `Build docs` 步骤失败，而它前面的
`Verify fact model` 与 `Check docs against repository` 都通过；本地构建也一切正常。

根因：`book/mkdocs.yml` 的 `plugins:` 里有 `glightbox`，而
`book/requirements.txt` **只列了 mkdocs / mkdocs-material / pymdown-extensions / jieba**
—— glightbox 是当初我用 `pip install` 手动装进本地 venv 的，**没有写进清单**。
于是 CI 装完 requirements 后，mkdocs 直接报
`Config value 'plugins': The "glightbox" plugin is not installed` 并中止。
`book.py check` 不跑 mkdocs，所以它能过 —— 这个"半个门禁"的缺口掩盖了问题。

修法：
- requirements.txt 补上 `mkdocs-glightbox==0.5.2` 与它的依赖 `selectolax==1.0.0`；
- 在文件里写清两条纪律：
  · `mkdocs.yml` 的 `plugins:` 引用什么，这里就必须列什么；
  · **"我本地能构建"不等于"requirements 是完整的"** —— 必须在**全新 venv** 里
    按本文件装一遍再构建（命令写在文件末尾）。

验证（实跑，不是推断）：在全新虚拟环境里
    python -m venv <tmp> && <tmp>/bin/python -m pip install -r book/requirements.txt
    <tmp>/bin/python -m mkdocs build --strict -f book/mkdocs.yml --site-dir <tmp>/out
→ 安装 exit 0、构建 **零警告** exit 0、产物 index.html 存在。
