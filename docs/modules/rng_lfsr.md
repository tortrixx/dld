## 1. 模块职责与在系统中的定位

<div class="plain-explain-box">
  💡 <strong>大白话一句话理解本模块</strong>：<br>
  它是游戏开局把零片随机打散在屏幕各处的<strong>“硬件掷骰子机”</strong>。它仅消耗 8 个触发器和几个异或门，就能根据标准的数学本原多项式滚出 255 步不重复的伪随机数。而且它极其守纪律：只有在开局散落时引擎按一下步进脉冲，它才翻转一次；内部还自带防死锁看门狗，万一遇到全 0 异常会自动强行弹回初始种子，确保系统永不卡死。
</div>

在提高要求 A3（零片散落位置随机）和 A2（第三关图案随机选择）中，系统必须具备确定性可控且硬件开销极低的随机数发生器。`rng_lfsr` 采用**8 位线性反馈移位寄存器（LFSR, Linear Feedback Shift Register）**实现，仅消耗 8 个触发器和 3 个异或门。

核心职责包括：
1. **生成 255 拍满周期伪随机序列**：基于本原多项式提供统计均匀分布的 8 位随机数；
2. **按需单步推进 (On-Demand Stepping)**：严格受控于消费者的 `i_step` 脉冲，绝不自由空转，保证仿真 100% 可复现；
3. **全零死锁自恢复保护**：内部集成防御性电路，彻底消除全零“吸收态（Absorbing State）”导致系统卡死的隐患。

## 2. 端口定义与信号传输机制

### 2.1 模块端口清单

| 端口名 | 方向 | 信号类型 | 连接目标 | 功能说明 |
|:---|:---:|:---:|:---|:---|
| `i_clk` | `in` | `std_logic` | `clk_gen` | 全局 50 MHz 主时钟基准 |
| `i_rst` | `in` | `std_logic` | `clk_gen` | 高电平同步复位，复位至初始种子 `0x5A` |
| `i_step` | `in` | `std_logic` | `puzzle_ctrl` | 单步推进使能脉冲（高电平时移位一次） |
| `o_val` | `out` | `std_logic_vector(7 downto 0)` | `puzzle_ctrl`, `puzzle_top` | 当前 8 位伪随机数值输出 |

### 2.2 信号传输机制

当拼图引擎在 `S_PREVIEW` 结束切入 `S_PLAYING` 散落零片时，引擎每需要一个新的锚点坐标，就拉高一次 `i_step`。LFSR 仅在该单拍内完成一次移位反馈，生成新的 8 位随机数供引擎取模切片。

## 3. 代码核心原理与微架构实现

### 3.1 本原多项式与 255 拍满周期设计

LFSR 能够产生最长序列的充要条件是其特征多项式必须为**本原多项式 (Primitive Polynomial)**。
本模块选用了国际公认的标准 8 位本原多项式（参考 Xilinx XAPP052 规范）：
$$P(x) = x^8 + x^6 + x^5 + x^4 + 1$$

在 VHDL 中，反馈函数实现如下：
```vhdl
fb := sr(7) xor sr(5) xor sr(4) xor sr(3);
sr <= sr(6 downto 0) & fb;
```
在此多项式驱动下，LFSR 将遍历除全 0 之外的所有 $2^8 - 1 = 255$ 种非零状态，周期严格为 255 步，且 8 个比特位中每一位出现 `'1'` 的先验概率严格收敛于 $128/255 \approx 50.2\%$，具有极优的统计均匀性。

### 3.2 为什么必须采用“按需单步推进”而不是“自由空转”？

许多初学者喜欢让 LFSR 跟着 50 MHz 主频每个周期都在跑。在工业级数字逻辑中，这是一种极其危险的做法：
1. **仿真不可复现**：按键按下时刻相对于 50 MHz 时钟相位存在微秒级浮动，自由空转会导致每次仿真的随机数完全不同，自动化测试断言根本无法验证；
2. **功耗浪费**：零片散落只在开局的一瞬间需要随机数，其他 99.9% 的时间都在白白产生翻转功耗；
3. **本工程解法**：`rng_lfsr` 仅在收到 `i_step = '1'` 时单步步进，测试台可以通过精确控制 step 步数实现 100% 确定性的激励回放。

### 3.3 全零死锁陷阱防御

在异或反馈 LFSR 中，`00000000` 是一个致命的**全零吸收态**：
* 若寄存器偶然因上电毛刺或辐射翻转进入全 0，所有的异或运算结果均为 0，LFSR 将永远被死死锁在全 0 状态，导致所有零片全部落入屏幕左上角 $(0,0)$ 无法散开！
* **硬件防御**：代码中增加了实时防御陷阱：
  ```vhdl
  if ((sr(6 downto 0) & fb) = "00000000") then
      sr <= SEED_DEFAULT; -- 强行弹回非零种子 0x5A
  end if;
  ```
  彻底杜绝了硬件在恶劣环境下的死锁可能。

### 波形图逐点细节剖析

1. **复位状态**：
   - 当 `i_rst = '1'` 时，输出 `o_val` 恒定锁定为初值 `0x5A`（`01011010`）；
2. **按需移位过程**：
   - 观察 `i_step` 脉冲，只有在 `i_step` 拉高的时钟周期，`o_val` 才会产生数值更新，其余时间保持静止；
   - 验证移位逻辑：`0x5A`（二进制 `01011010`）经过反馈抽头计算出下一位反馈为 `0`，新值为 `0xB4`，波形数值与理论真值逐拍严格对齐；
3. **中途复位重演性**：
   - 在推进多步后再次施加 `i_rst` 脉冲，输出立即无条件准确回归 `0x5A`，且后续重新生成的伪随机序列与前一轮完全一致，证明可复现性 100% 成立。

## 5. 极限资源优化与避坑总结

* **条件相减取模优化**：
  - 散落时需要将 8 位随机数映射到屏幕边界（例如行上界 $9-h$、列上界 $9-w$）。常规的除法取模（`%`）会生成极其昂贵的硬件除法器（需要 100+ LE）；
  - 我们在 `puzzle_ctrl` 中改为**“一次比较 + 条件相减”**：将 8 位拆成两段 3 位数，若大于上界则减去上界，仅消耗 2 个减法器，资源几乎为零！

## 6. 🎓 老师答辩必问与标准回答（核心快问快答）

<div class="defense-box">
  <div class="defense-title">💡 老师随机抽查：随机数生成器核心答辩点</div>

  <div class="defense-q">Q1：你们的随机数是用什么原理产生的？多项式是什么？</div>
  <div class="defense-a">
    <strong>标准回答：</strong><br>
    老师，我们采用的是硬件中经典的<strong> 8 位 Galois/Fibonacci 线性反馈移位寄存器（LFSR）</strong>。<br>
    我们选用的本原多项式是国际标准规范中的：<br>
    \[ P(x) = x^8 + x^6 + x^5 + x^4 + 1 \]<br>
    由第 7、5、4、3 位作为抽头进行异或运算后反馈回最低位。它的最大周期是 \(2^8 - 1 = 255\) 拍满周期，状态分布非常均匀，且硬件只需要 8 个触发器和几个异或门，极其轻量高效。
  </div>

  <div class="defense-q">Q2：为什么你们的 LFSR 没有一直跟着 50 MHz 跑，而是用 i_step 驱动？</div>
  <div class="defense-a">
    <strong>标准回答：</strong><br>
    主要基于两点核心工程考量：<br>
    1. <strong>可测试性与可复现性</strong>：如果 LFSR 自由空转，按键的微秒级抖动会导致每次开局的随机数彻底随机，仿真测试台将无法编写自动化断言进行回归校验。改为 <code>i_step</code> 单步按需推进后，每一局的随机散落过程都是 100% 确定可复现的；<br>
    2. <strong>超低功耗</strong>：芯片只在关卡初始化散落零片的十几拍内需要随机数，按需推进避免了时钟树全天候无效高频翻转。
  </div>

  <div class="defense-q">Q3：LFSR 遇到全 0 为什么会死机？你们是怎么解决的？</div>
  <div class="defense-a">
    <strong>标准回答：</strong><br>
    在纯异或反馈的 LFSR 中，如果所有位都是 0，那么 \(0 \oplus 0 = 0\)，移位后依然是全 0。这被称为<strong>全零吸收态</strong>，一旦陷入就永远出不来，所有零片都会堆在 $(0,0)$。<br>
    我们在硬件中做了防御设计：复位时强制装载非零种子 <code>0x5A</code>；同时在组合移位路径末端增加了全零检测比较器，一旦检测到即将进入全 0，硬件会自动将其强行置回非零初值，彻底消除了死锁风险。
  </div>
</div>
