### 1.2 ⚠️ 面积为什么从 958 LE 涨到 1201 LE（**ERR-019 阶段的历史记录，别当成退步**）

第 2 阶段仿真抓出的 **ERR-019**（`srl8` 移位方向反了）修正之后，面积从
**958 LE（75%）涨到 1201 LE（95%）**，Fmax 从 42.24 MHz 降到 41.39 MHz。

原因不是"代码写啰嗦了"，而是**旧的错误方向让综合器白捡了便宜**：

* 错误的**左移**会把零片形状里**低列**的格子推出边界 → 锚点列 ≥ 3 的那几路输出
  恒为 0 → Quartus 把这些逻辑**常量折叠**掉，整片移位网络被剪掉一大块；
* 正确的**右移**必须把格子搬到高列，**每个锚点列都真的要用** → 无法折叠。

验证：把方向改回错误的写法重建，面积立刻回到 **967 LE**；再改回正确写法又是
**1201 LE**；连"位序反转→左移→再反转"的等价改写**也是 1201 LE**（等价函数综合后
就是同一张网表）→ 证明这个代价是**方向正确本身**带来的，不是写法问题。

**处置**：接受 95%（仍能放下，余量 69 LE，fitter 0 error，`.pof` 正常生成），并把它
写进报告"已知不足"。**绝不能为了面积好看而保留一个把零片画错列的 bug。**

> ⚠️ **2026-10-08/09 后续更正（数字已变，结论不变）**：ERR-019 之后又修了 **ERR-020**
> （方向与移动请求同拍锁存，+1 LE → **1202 LE**）与 **ERR-021**（成功判据改为整帧画面比较，
> → **1187 LE**）、**ERR-023/ERR-024**（去鬼影 + `shuf_seen`，→ **1191 LE**）、
> **结算画面改版**（`WIN_MASK` 换笑脸 + 3 位 `endflash_cnt`，→ **1188 LE**）、
> **修闪烁**（ERR-027，零代价）、**结算数码管改版**（ERR-030：字母译码表 +6 LE，→ **1194 LE**）、
> **胜利图案二次改版**（笑脸 → 粗红对勾，只换常量，→ **1195 LE**）。
> 当前实测 **1195 / 1270 LE（94%）**、余量 75 LE、Fmax 仍 **41.39 MHz** ——
> 判据改整帧比较时"面积不升反降"，其余改动都只是 **±6 LE 以内的波动**。
> 上面 958 → 1201 的受控实验记录**予以保留**，它证明的结论不变：
> **"面积小"当年确实是那个错误移位的副产品。**

## 4. 故障记录（**编译期**，完整版见 `docs/06`）

| 编号 | 现象 | 根因 | 修法 |
|---|---|---|---|
| **ERR-001** | 编译通过，但 Fitter 报 `No exact pin location assignment(s) for 1 pins of 52` | 生成器的端口清单**漏写 `btn`** → 未被约束，落到 `PIN_50`（复位键完全没反应） | 补 `btn`；加**第一道守卫**（列出的端口必须在引脚表中） |

| **ERR-014** | `.qsf` 打不开工程 | 用了 `--` 写注释（**VHDL 风格**）；`.qsf` 必须用 `#` | 改 `#` |
| **ERR-015** | `Error reading Settings File`（device options 行） | `ENABLE_CONFIGURATION_PINS` 在 MAX II / 9.1 上**不是合法赋值名** | 删除该行 |

### 4.1 两条守卫的作用范围（**教训**）

* 第一道守卫只能看到**你列出的端口** → **抓不到"漏列端口"**（ERR-002 正是钻了空子）；
* 因此加了第二道：解析 `rtl/<top>.vhd` 的 **entity 端口列表**，任何未列入的端口**直接报错退出**。
* **守卫自身也要被审查**：第二道守卫第一版匹配到了注释里的 "is" 一词，只解析出 1 个端口 ——
  **一个少报的守卫比没有守卫更危险**（它看起来检查过了）。修正为**先剥注释再解析**。

| 项 | 值 |
|---|---|
| `.sdc` 约束 | 50 MHz（周期 20 ns） |
| **实测 Fmax** | **41.39 MHz**（周期 24.16 ns）—— `quartus_sta` 的 Fmax Summary（TimeQuest） |
| 是否满足约束 | ❌ **未满足** |
| 关键路径（最差 slack −4.160 ns） | `game_fsm:u_fsm\|level` → `puzzle_ctrl:u_puzzle\|sc_cand[3]`（散落的候选锚点计算，含 `mod ch`/`mod cw` 两个 `lpm_divide`） |
| **功能风险** | **低** —— 本设计所有外设都是**人机接口**（按键 / 点阵 / 数码管 / 蜂鸣器），实际工作频率需求 < 1 kHz，41 MHz 有 **4 万倍**余量 |

**已做的流水化**（关键路径 26 ns → 24.2 ns）：

| 序 | 原关键路径 | 处置 |
|---|---|---|
| 1 | `disp_format` 的 `t/10`、`t mod 10` 推出 **`lpm_divide`** 进位链（26 ns） | 换成 **64 项查找表**，该处除法器消失 |
| 2 | `pos → o_solved → 音效多路器 → buzz` | 状态标志与音效码各**加一级寄存器** |
| 3 | `sel → 锚点多路 → 边界比较 → 启动检查引擎` | 移动请求**两拍流水** |
| 4 | `pos → 相减 → 范围比较 → row_mask 移位` | **行号加一级寄存器**；`srl8` 由逐位循环改 **7 路 mux 树** |

> ⚠️ 第 2 阶段仿真修 ERR-019 之后，面积涨到 95%、Fmax 略降到 41.39 MHz（原因见 §1.2）。
> **当前（胜利图案改粗红对勾之后）面积为 1195 / 1270 LE（94%）**，Fmax 与关键路径均未变差。
> ⚠️ **下一轮注意（A2/S1 图案库随机选择，见 `HANDOFF.md` 顶部清单）**：每关加 3~4 幅候选图案会
