# 显示与音效驱动（disp_format / seg_scan / dot_matrix_scan / buzzer_ctrl）

> **一句话**：把秒数、胜负和图案显示出来，并让蜂鸣器按曲子响。

## 1. 它管什么

- **吃进**：游戏主控的 `i_state`（3 位）、`i_time`（6 位秒数）、`i_level` 与 `i_lvl3`（各 1 位关卡号）。
- **吃进**：格式化器**送出**的 `o_data`（32 位，8 个 BCD 半字节）与 `o_blank`（8 位消隐掩码），接到 `seg_scan` 的 `i_data`、`i_blank`；拼图引擎的 `i_colr`、`i_colg`（各 8 位）。
- **吐出**：`o_seg`、`o_cat`（各 8 位）驱动 8 位数码管；`o_row`、`o_colr`、`o_colg`（各 8 位）驱动 8×8 双色点阵；`o_buzz`（1 位）驱动蜂鸣器。
- **节拍**：全部挂在 50 MHz `i_clk` 上；位选只在 `i_tick` 为 '1' 的那一拍推进，乐句只在 `i_t4` 为 '1' 的那一拍换音。
- **总开关**：`i_en` 为 '0' 时显示与发声一起压掉（SW7）；`i_rst` 把位选、段线和行线归位。
- **代价**：格式化器实测 17 LE（报告 §2.1）；整机 1,264 / 1,270 LE（99.53%），127 / 127 LAB 已占满。

## 2. 它在系统里的位置

![字符拼装波形](../assets/images/GUI-disp_format.png)
*字符拼装波形：状态和秒数进来，8 个 BCD 半字节与 8 位消隐掩码出去*

- **上游**：游戏主控给状态、秒数与关卡号；拼图引擎给当前行的红、绿两路列数据。
- **下游**：数码管的段线与位选线、点阵的行线与红绿列线，以及蜂鸣器那一根输出线。
- **少放它一个会怎样**：玩家看不到秒数、看不到拼图进度，也听不到任何提示，只剩键盘还能按。
- **极性一句话**：段高电平点亮、位选低电平选通；点阵行低电平选通、红绿列高电平点亮。
- **段序陷阱**：段线必须按 AA→PIN_62 到 AG→PIN_52 排，写反了仿真照样自洽，只有上板才看得出来。

## 3. 三个设计选择

### ① 用 64 项常数表替掉除法器

倒计时要把秒数拆成十位和个位。`/ 10` 与 `mod 10` 会被综合成 lpm_divide，报告里这条路径要 26 ns，只够跑到 39 MHz，而一个时钟周期只有 20 ns，装不下。

秒数最大 63，值域小得可以穷举：0～39 在 `case t` 里逐个列出十位与个位，40～63 走 `when others`，用减 40、减 50、减 60 三条区间判断补上。

代价是代码变长，收益是面积和时序：报告实测整个格式化器 17 LE，这条路径也不再是最慢的一条。

### ② 每位刷新率取 125 Hz

8 个位的段线并联在一起，正极共用、负极各自一根，所以同一时刻只能亮一位，必须轮流点。

顶层给的 `i_tick` 是 1 kHz，8 位轮一圈，每位就是 1000 ÷ 8 = 125 Hz，高于人眼约 50～60 Hz 的闪烁门槛。

曾经按 200 Hz 设计，每位只有 25 Hz，用户实测反馈数码管闪得比较明显；顶层因此把节拍从 `tick_200` 换成 `tick_1k`，`seg_scan` 本身没改一行。

### ③ 段码和位选同一沿更新

换位时如果新位选先到、段码晚半拍，上一位的残影就会串到下一位，看起来是重影。

`seg_scan` 把 `seg_r` 和 `cat_r` 放在同一个 `rising_edge` 里赋值，两者同拍换值，中间不存在半拍的重叠。

点阵那一路是同一个写法：`o_row` 与 `o_colr`、`o_colg` 一起寄存，一行不会被别行的数据点亮。

## 4. 波形怎么读

![数码管扫描波形](../assets/images/GUI-seg_scan.png)
*数码管扫描波形（在图上找：① `o_cat` 的独热位左移 ② `o_seg` 与它同拍换值 ③ `i_en` 拉低后 `o_seg` 归零）*

1. **① 0.05 µs 起**：`i_tick` 每 40 ns 一拍（仿真折算值，真实是 1 kHz），`o_cat` 每拍左移一位，从 `11111110` 走到 `01111111` 再回卷，说明位选是独热、低电平选通。
2. **② 0.72～1.36 µs**：这一段 `i_data` 是 `0x00000090`，`o_seg` 由 `00111111`（数字 0）换成 `01101111`（数字 9），与 `o_cat` 同一沿换值，段码没落后半拍。
3. **③ 4.56～5.20 µs**：`i_en` 拉低后 `o_seg` 恒为 `00000000`，而 `o_cat` 仍在按 `11111110`、`11111101` 的顺序扫描，说明全屏熄灭靠段线清零，不是停位选。

![点阵行扫描波形](../assets/images/GUI-dot_matrix_scan.png)
*点阵行扫描波形（在图上找：① `o_row` 始终只有一位是 '0' ② 换行那一沿 `o_colr`、`o_colg` 同时换值）*

**点阵这一路**：`o_row` 每 160 ns（仿真折算值，真实是 1 kHz 的 1 ms）从 `11111110` 左移到 `01111111`，同一时刻只有一位是 '0'。所以 64 个点并不是同时亮的，是被拆成 8 行轮流点亮的。

![蜂鸣器分频波形](../assets/images/GUI-buzzer_ctrl.png)
*蜂鸣器分频波形（在图上找：① `o_buzz` 的周期随 `i_sel` 变化 ② `step` 与 `tone_sel` 一起换步）*

**蜂鸣器这一路**：`i_sel` 从 `0000` 走到 `1111` 再回卷，`o_buzz` 的周期跟着变；`cnt` 数到 `half` 就翻转 `wave`，`step` 与 `tone_sel` 就是三关旋律的换步。

## 5. 答辩问答

### Q1 数码管显示秒数，除以 10 你是怎么做的？用除法器了吗？

A：没用除法器。`disp_format` 里用 `case t` 把 0～39 逐个列出来，40～63 走 `when others`，用减 40、减 50、减 60 三条区间判断补上。

`/ 10` 那条路径要 26 ns，只够跑到 39 MHz；报告实测整个格式化器 17 LE。

### Q2 125 Hz 这个刷新率怎么来的？我把它改成 200 Hz 行不行？

A：不行。`seg_scan` 的位选由 `i_tick` 推进，1 kHz 分给 8 位，每位 1000 ÷ 8 = 125 Hz。

按 200 Hz 算每位只有 25 Hz，用户实测反馈数码管闪得比较明显，顶层才把节拍换成 `tick_1k`。

### Q3 点阵上的黄色是怎么出来的？行和列的极性给我说清楚。

A：行低电平选通、列高电平点亮。`o_row` 同一时刻只有一根是 '0'。

`o_colr` 与 `o_colg` 的同一位同时为 '1' 时，红、绿两颗管芯一起亮，眼睛看到的就是黄色；驱动是直通的两个位平面，不强制红绿互斥。

### Q4 蜂鸣器的音高是怎么分频出来的？三关的背景音乐差在哪？

A：50 MHz 经 ÷256 预分频得到 195.3125 kHz，`cnt` 数到 `half` 就翻转 `wave`：E5 取 148 拍、G6 取 62 拍。

误差 0.59%～1.25%，小于人耳可分辨的约 1.5%；三关 BGM 是 `i_sel` 的 1000、1001、1011 三个码，各查一张 16 步旋律表。

### Q5 我把 SW7 拨下来，数码管和点阵分别是怎么灭的？

A：两边不一样。`seg_scan` 在 `i_en='0'` 时只把 `o_seg` 清成 `00000000`，`o_cat` 照常独热扫描。

`dot_matrix_scan` 在 `i_en='0'` 或 `i_rst='1'` 时把 `o_row` 全置 '1'、`o_colr` 与 `o_colg` 全置 '0'，整个面板灭掉。
