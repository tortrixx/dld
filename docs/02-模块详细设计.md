## 1. `puzzle_pkg` —— 唯一真值源

**为什么单独成包**：位序约定、图案数据、时序常量**只能定义一次**。
参考仓库曾因"图案与零片各自定义"导致 11 格与 12 格不守恒。

**位序约定**（全项目统一）：

```
mask 位号 = 8*行 + 列 ，bit0 = 左上角
→ 向下移动 (行+1) = 位号变大    向右移动 (列+1) = 行内位号变大
→ 锚点打包 = 行(3:0) & 列(3:0)
```

**关键纯函数**：

| 函数 | 作用 | 为什么要它 |
|---|---|---|
| `srl8(r, dc)` | 8 位行右移 dc 列 | **写成 7 路 case 而不是逐位循环**：逐位形式让 Quartus 为每一位生成"加法+比较+选择"网络，实测成为关键路径（41.5 MHz，要求 50 MHz） |
| `row24(shp24, sr, ac)` | 取零片第 sr 行、按锚点列 ac 移位后的 8 位行掩码 | 重叠判定与渲染**共用**；单用途小函数，避免调用点复制 |
| `popcount(m)` | 数 1 的个数 | 离线核对与自检 |
| `shift_mask(m, dr, dc)` | 任意位移（保留作教学/核对） | **主路径不使用**（见 §4 面积史） |

## 2. `clk_gen` —— 时钟与复位

**串行级联分频**（只有第一级面对 50 MHz）：

```
50MHz ──/50000──> 1kHz(1ms) ──/5──> 200Hz ──/2──> 100Hz ─┬─/50──> 2Hz
                                     │                    └─/100─> 1Hz
                                     └──/5──> 40Hz
```

**各 tick 的用途（2026-10-08 校正，ERR-027）**：

| tick | 周期 | 谁在用 | 说明 |
|---|---|---|---|
| `tick_1k` | 1 ms | 对局秒表/复位计时 + **显示扫描** | 点阵行推进（`mrow`）与数码管位选（`seg_scan.i_tick`）都走它 → **125 Hz 扫描** |
| `tick_200` | 5 ms | **只剩键盘扫描** | 键盘扫描一轮 = **2 个 tick_200 = 10 ms**（`SC_ALL_HIGH` 与 `SC_ALL_LOW` 各等一个 tick）；消抖 `DEBOUNCE_MAX+1 = 4` 轮 = **40 ms**（2026-10-09 由 16 轮缩到 4 轮，见 ERR-031）；显示已不再使用 |
| `tick_100` | 10 ms | 2 Hz / 1 Hz 分频链 | 只作分频中间级 |
| `tick_40` | 25 ms | **已不再被任何模块使用** | 当年为"扫描/渲染同源"加的；ERR-027 把显示扫描统一到 1 kHz 后它就空出来了。**输出保留**（不动 `tb_clk_gen` 的节拍断言），只把注释改成"不再使用" |
| `tick_2hz`/`tick_1hz` | 500 ms / 1 s | 自检闪烁 / 倒计时 | `tick_2hz` 是**单时钟脉冲**，闪烁必须另做 50% 方波（ERR-011） |

**三条设计要点**：

1. **串行级联而不是并行分频**：并行分频每级都要面对 50 MHz 做比较，计数器位宽大、比较器长；
   级联后除第一级外都只"数上一级的脉冲"，面积与关键路径都小。
2. **上电复位数 `tick_1k` 而不是数 `clk`**：直数 50 MHz 需要 19 位计数器，
   数 1 kHz 只要 4 位。且 `tick_1k` 由自由运行的分频链产生、**不依赖复位**，上电即可用。
3. **饱和计数**：`por_cnt` 计到上限就停，**永远不会回绕** → 不可能产生"二次复位"。

**按键复位消抖**：20 位全 1 移位寄存器。上电初值为全 1，
即"已稳定按下 20 ms"——因为移位寄存器只有真的持续为 1 才会保持全 1，**不会产生幻影复位**。

## 3. `keypad_scan` —— 键盘扫描

**扫描方案**：四列**全部驱动**，每相只有一个 `'0'`：

```
col = "1110" / "1101" / "1011" / "0111"      （相 0/1/2/3）
```

**极性常量**（全项目唯一的极性定义点）：

```vhdl
constant KP_ACTIVE : std_logic := '0';   -- 按下时该行读 '0'
```

**实测确认**（2026-10-08，`keypad_diag_top`）：不按键时行线为高低不定，
但**任一键按下时确实有行线变为 `'0'`** → `KP_ACTIVE='0'` 正确。

**状态机**：`ST_IDLE → ST_SETTLE(64 clk) → ST_SCAN(相0) → ST_SETTLE → …`，
每相稳定 64 个时钟再读，读到的键码写入 `round_code`，扫描轮末被消抖级采样。

**消抖**：需连续 `DEBOUNCE_MAX+1` 轮读数一致才接受。⚠️ **一轮 = 2 个 `tick_200` = 10 ms**
（`SC_ALL_HIGH` 等一个 tick、`SC_ALL_LOW` 再等一个 tick），所以
`DEBOUNCE_MAX = 3` → **4 轮 = 40 ms**（2026-10-09，ERR-031：旧文档写的"16 轮 = 80 ms"
把 2 倍算漏了，板上真实值曾是 **160 ms**，用户反馈"防抖时间有点长"）。
接受后 `o_press` 给出**单时钟脉冲**（保证一次按下只触发一次动作）；实测按下→`o_press`
约 **45 ms**（`tb_keypad_scan` 断言 ⑨ 实测 9T，原来是 33T = 165 ms）。

### ⚠️ 本模块踩过的坑（ERR 记录素材）

| # | 症状 | 根因 | 修法 |
|---|---|---|---|
| K1 | 整机"按任何键无反应" | **列驱动是寄存的、相号是同拍更新的**：tick 后第一个周期 `phase` 还是上一轮的 3，而 `col_drv` 已变成相 0 的 `"1110"` → **驱动的列与用来组码的列号不一致**，每相都错位一列 | 列驱动改为**对 `phase` 纯组合**，两者不可能不一致 |
| K2 | 未按键时四行读数为 `1 0 1 0`（应全 1） | 键盘行线未接上拉 / 空闲电平不确定 | 待接线确认；扫描本身靠"哪一行为 `KP_ACTIVE`"判断，**不依赖空闲电平** |

## 4. `puzzle_ctrl` —— 拼图核心（**本项目面积优化的主战场**）

### 4.1 职责边界

**只管空间，不含任何计时**。
计时/关卡/倒计时全在 `game_fsm`。这条边界让两个模块各自可独立仿真与替换。

### 4.2 数据模型（**只存 36 个触发器**）

```
pos     : 4 × 8 位打包锚点 = 32 位        （每块零片包围盒左上角，行(3:0)&列(3:0)）
locked  : 4 位                            （是否已"确认"锁定）
```

**零片的绝对占位、颜色、重叠判定全部是导出的**，不存储。
这是与参考仓库最大的结构差异，也是能塞进 EPM1270 的关键。

### 4.3 ⭐ 面积演进史（每一步都是**实测**，不是估计）

| 版本 | 做法 | 实测 LE | 结论 |
|---|---|---|---|
| v1 | 每块零片用 64 位**变距移位**算"形状移到 (行,列)" | **4690** | 64×6 交叉开关，超出器件 3.7 倍 |
| v2 | 同上，但用"逐行 CASE"辅助函数 | **2969** | 仍太大 |
| v3 | 循环里**变址读数组**（`inst_mask(k)`、`i_shape_h(k)`） | **2995** | 每次变址读都变成 64 位/8 位多路器，且**每个使用点各复制一份** |
| v4 | 固定移位维护 64 位占位寄存器 + 渲染多路器 | **2350** | 寄存器 504 个（占器件 40%），LUT-only 1717 |
| v5 | **改行扫描渲染**（每拍只算一行，8 位累加器） | **3751** | 寄存器降到 115，但未展开的重叠判定实例化了 32 个 `row_mask` |
| **v6** | **重叠判定也串行化：每拍比一行** | **994** | 任一时刻只有一个 `row_mask` 存活 → 可共享 |
| v7 | 关键路径流水（见 §4.5） | **563** | 最终值 |

**核心教训**（写进报告"故障分析"）：

> 面积不是被"某一条语句"吃掉的，而是被**"宽向量 + 变址访问 + 未展开调用"**这三件事的
> **复制效应**吃掉的。每一次把"必须同时算完"改成"分拍算"，LE 就成百地掉。
> **判断依据只能来自 map 报告的层次面积表与 TimeQuest 的路径报告，不能靠估计。**

### 4.4 渲染：行扫描引擎

点阵驱动本来就是**一行一行扫**的，所以引擎**只算"驱动即将显示的那一行"**：

```
每拍 (i_tick = tick_200，200 Hz；点阵行扫描另走 1 kHz)：
  对每块零片：若该行落在它的包围盒内
      取相对形状第 (行-锚点行) 行 → 按锚点列右移 → 8 位行掩码
      覆盖掩码 |= 该行        选中/已锁 → 绿色掩码 |= 该行
  （ERR-023 后**不画目标虚影**：目标图案只供成功判据）
  把这一行写入 64 位帧寄存器（帧彩色的对应 8 位切片）
```

**颜色规则**（要求 B6 / B8）：

| 颜色 | 条件 | 实现 |
|---|---|---|
| 绿 | 该格属于**选中的**零片 | 绿=1、红=0 |
| 黄 | 该格属于**已锁定**的零片 | 红=1、绿=1（点阵双色同时亮即黄） |
| 红 | 该格属于**未选中**的零片（ERR-023 后不再画"目标图案但无零片"的红色虚影） | 红=1、绿=0 |

**两个"率"要分开（2026-10-08 更正，ERR-027）**：

* **扫描率（亮度调制）= 125 Hz**：顶层 `mrow` 每 `tick_1k`（1 kHz）推进一行，8 行 = 8 ms → **125 Hz**；
  数码管位选（`seg_scan.i_tick`）同样走 `tick_1k` → **每位 125 Hz**。**占空比仍是 1/8，亮度不变**，
  只是不再闪（25 Hz 低于 LED 的临界闪烁融合 ~60 Hz）。
* **内容/帧更新率 = 25 Hz**：引擎行渲染 `i_tick` 仍是 `tick_200`（8 拍一帧 = 40 ms）。
  ⚠️ **受控实验**：把 `i_tick` 也提到 1 kHz，整机从 **1188 → 1264 / 1270 LE（100%，只剩 6 个）**，
  （该实验的基数是当时的 1188 LE；其后"结算数码管改版"的字母译码又 +6 → 1194 LE，
  "胜利图案改粗红对勾"再 +1 → **现为 1195 LE**）
  即 **+76 LE 而收益为零** —— 闪烁只由**扫描率**决定，与"画面内容更新率"无关，所以引擎保持 200 Hz。
* **如实记录的残余**：内容仍按 25 Hz 更新，因此"移动零片后，画面逐行刷新会滚过 ≤40 ms"
  （轻微 tearing/涂抹，人眼在按键节奏下不可见）；要消除需 +76 LE，当前 94% 面积下**不值得**。

**⭐ 成功判据（ERR-021 之后改为"整帧画面判据"）**：渲染器在扫描每一行时**顺便**比较
"本行被零片覆盖的格子"（`cov`）与"目标图案本行"（`tgtrow`），**8 行全等 ⇔ 零片并集 == 目标图案**。
判据只在**整帧画完**时发布（`frm_ok`），并要求这一帧内 `pos` 与 `level` 没变过
（`pos_frm`/`lvl_frm` 快照 → `frm_valid`），否则一帧里可能混着两种摆法的行，把错的看成对的。
原判据是"第 k 块的锚点 == 写死的 `L*_TGT[k]`"，**过强**：同一幅画面有多种等价摆法
（第二关 4 块完全相同的 2×2 有 4! = 24 种），玩家拼对了也会被判失败 —— 详见 `docs/00` §1.4 与 `docs/06` ERR-021。

**ERR-021 新增的寄存器（见 `rtl/puzzle_ctrl.vhd` 的 ERR-021 注释块）**：

| 信号 | 含义 |
|---|---|
| `frm_bad` | 当前帧出现过"某行不匹配" |
| `frm_ok` | 上一整帧（且未被扰动）的并集 == 目标图案 |
| `frm_valid` | 上一整帧是"干净"的一帧（判据可用） |
| `pos_frm` / `lvl_frm` | 帧首快照的 `pos`/`level`，用于判断本帧是否被扰动 |

对外语义：**`o_solved = frm_ok and alllock_r`**（画面正确 **且** 全部已确认锁定）；
**`o_all_lock = alllock_r and frm_valid`**（"全部锁定"对外意味着**判据齐备**，最多等一帧 = 40 ms，
避免刚确认最后一块的那一拍拿上一帧的旧判据，把"拼对"又误判成失败）。
判据由"4 个 8 位锚点比较器"换成"1 个 8 位整帧比较 + 快照寄存器"，**面积不升反降**（见 `docs/05` §1）。

**`i_target` 的新语义（ERR-023）**：`i_target` **恒为真实目标图案**（顶层 `puzzle_top` 直接接
`tgt_mask`），它现在的唯一用途就是**成功判据**（`tgtrow` 与之逐行比较）。**引擎不再画目标鬼影** ——
对局态本来就不该有虚影（ERR-013），以前是靠"顶层把 `i_target` 置零"来消虚影，代价是判据永不成立
（上板：拼对了仍出叉）。改法是把"消虚影"放回引擎内部（`redrow := cov and (not selrow)`），
`i_target` 就能一直保持真实；预览的完整图案由顶层 `prev_row` 画出，**对局画面与以前完全一致**。
可执行判据：`docs/03` 的 puzzle_ctrl 断言 ⑧（"未覆盖的目标格子必须不亮"）与整机断言 ⑩（r12 8/12 → r14 12/12）。

> ⚠️ **这里踩过两个真坑**：
> ① 早期版本"每 5 拍发布一行" → 帧率只有 `200/(5×8) = 5 Hz`，**肉眼明显闪烁**；
> ② 引擎按 `tick_200` 推进行、点阵按 `t_40` 扫描，**两个计数器不同源**，
>    "正在显示的行"与"正在渲染的行"长期不一致 → 表现为闪烁/撕裂。
> **修法：两者同源同拍推进**。这条判据（"显示与渲染必须同源"）是本项目最贵的经验之一。
>
> ⚠️ **2026-10-08 补记（ERR-027）**：把两边都改成 200 Hz 只消掉了"错行"，**帧率仍只有 25 Hz**，
> 上板依旧可见闪。现在**扫描侧**（`mrow` + `seg_scan`）统一到 1 kHz → 125 Hz，
> 引擎内容仍 200 Hz；因为引擎帧寄存器是"整帧持有、按行切片"的，**扫描比内容快 5 倍不会重新引入错行**。
> 详见 `docs/06` **ERR-027**。

### 4.5 关键路径优化（41.5 MHz → 39.8 MHz 期间的流水化）

TimeQuest 报告的关键路径逐个被消除：

| 序 | 报告路径 | 处置 |
|---|---|---|
| 1 | `t/10`、`t mod 10` 推 `lpm_divide` 进位链（26 ns） | 换成 **64 项查找表**，除法器彻底消失 |
| 2 | `pos → o_solved → fsm 音效多路器 → buzz` | `o_solved`/`o_all_lock` **加一级寄存器**；音效码也加一级 |
| 3 | `sel → 锚点多路 → 边界比较 → 启动检查引擎` | 移动请求**两拍流水**：先锁存"原锚点+方向"，下一拍再做钳位与边界判定 |
| 4 | `pos → gref 行相减 → 范围比较 → row_mask 移位` | 行号**加一级寄存器**；`srl8` 由逐位循环改为 7 路 case |

## 5. `game_fsm` —— 主状态机

**状态编码**（3 位，6 态，不用 one-hot 以省面积）：

| 编码 | 状态 | 行为 | 要求 |
|---|---|---|---|
| `000` | `S_SELF_TEST` | 2 秒；点阵全黄 2Hz 闪；8 位数码管全"8"且闪 | B1 |
| `001` | `S_IDLE` | 点阵灭；DISP7="5"、DISP0=关卡号 | B2 / B3 |
| `010` | `S_PREVIEW` | 完整图案 5 秒；DISP7 倒计时 | B4 |
| `011` | `S_PLAYING` | 拼图限时（一关 30 s / 二关 40 s / 三关 40 s）；DISP4:DISP3 倒计时 | B5 / B10 / A2 |
| `100` | `S_WIN` | 胜利结算：**绿色粗对勾**（自拟 `WIN_MASK`，24 格、笔画 3 格宽），先闪后常亮；数码管最左四位 `PASS` | B10 / A2 / S5 |
| `101` | `S_FAIL` | 失败结算：**红色叉**（原 `FAIL_MASK`，未改），先闪后常亮 | B9 / B10 / S5 |

**关口表示（2026-10-09 第 12 工作阶段 / D2：三关）**：关数**不是**一个 2 位总线，而是
**`level`（原有 1 位）+ `lvl3`（新增 1 位）** 两个信号：

| `level` | `lvl3` | 关口 | 图案 | 零片 | 限时 |
|---|---|---|---|---|---|
| `0` | `0` | 第一关 | 图 4-1（B4 指定） | 3 块 | 30 s |
| `1` | `0` | 第二关 | **固定 PAT3 阶梯**（B10 自拟但固定） | 4 块异形 | 40 s |
| `1` | `1` | **第三关（A2 新增）** | **四幅库随机选** | 4 块异形 | 40 s（自拟 `T_LEVEL3`） |

过关链：一关拼对 → `level<=1`（进二关预览）；二关拼对 → `lvl3<=1`（进三关预览）；
三关拼对 → `S_WIN`。任何"新开一局"（【开始】/SW7 拨动/复位）都把 `level` 与 `lvl3` **一起清零**。

> ⭐ **为什么不用 2 位总线**：这是**实测**的决定，不是风格 —— 把 `o_level` 直接加宽成
> `std_logic_vector(1 downto 0)` 会在 `piece_rom` / `pattern_rom` / `puzzle_ctrl` 前面
> 各插一级比较器，同一个第三关功能让 Fmax 从 48.87 掉到 46 以下（13 个 fitter seed 的最好值）；
> 保持那位寄存器不动、另加一个独立标志则几乎不掉。两种写法都用 `.tmp/opt/opt_build.py` 真编译量过，
> 数据见 `docs/00` §4.1。**在 98% 占用率下，"动了哪根既有网"比"加了多少逻辑"重要得多。**

**关键设计**：

1. **`SW7=0` 强行回到自检起点**：拨回来一定看到完整自检/待机，不会"接着半局游戏"。
   **【开始】键在任意时刻都有效（B11）**：待机/预览/对局/结算按下都回到"新一局"，含**对局中重开**
   （该分支的仿真断言 **⑱** 是 2026-10-09 收尾补齐的，见 `docs/03` game_fsm 小节）。
2. **散落请求用"请求/应答"握手**（`o_go` 保持到 `i_shuf_busy` 变高再撤），
   而不是单拍脉冲——**无论散落耗时多少拍都不会丢请求**。
3. **判定语义**（B9 的自洽读法；ERR-021 之后按"画面"判，ERR-024 之后还要求"本局散落已跑过"）：
   - `i_solved`（**整帧画面 == 目标图案** 且全部零片已确认锁定）→ 过关；
   - `i_all_lock`（全部已确认锁定**且整帧判据已就绪**）**且引擎空闲** → 全锁完但画面不对 → 失败；
   - 两条判决都还要求 **`shuf_seen='1'`**（本局至少见过一次散落忙态）且 **`i_shuf_busy='0'`**（引擎空闲）；
   - 倒计时到 0 → 失败。

   > ⚠️ **2026-10-08 更正（ERR-021）**：这里原来写的是"`i_solved`（全部锁定**且**都在目标锚点）→ 过关"。
   > 上板实测"第二关拼对仍然出叉"，根因就是那个锚点判据只认 24 种等价摆法里的 1 种。
   > 现改为**整帧画面判据**（在 `puzzle_ctrl` 内实现，见 §4.4 的成功判据）；`game_fsm` 侧接口语义不变。

   > ⚠️ **2026-10-08 再更正（ERR-024）**：`puzzle_ctrl` 的 `locked/pos` 只在散落（`i_go`）时清零，
   > 所以刚进 `S_PLAYING` 的一两拍里，引擎里还是**上一局**的状态。旧实现无条件采信
   > `i_solved`/`i_all_lock`，于是"上一局拼错 → 新一局刚开局就判负"、"上一局拼对 → 新一局刚开局
   > 就过关、直接跳第二关"（上板现象："退出重进直接又跳入第二关"）。新增 **`shuf_seen`**：
   > 本局见过散落忙态之后判决才生效（胜负音效同样门控）。证据：`game_fsm` 断言 ⑯⑰
   > （r07 **15/17** → r09 **17/17**），详见 `docs/06` ERR-024。
4. ⚠️ **2Hz 闪烁必须是方波**：`clk_gen` 的 `tick_2hz` 是**单时钟脉冲**，
   直接当"闪烁电平"用等于"每 500 ms 只亮一个时钟"——**肉眼几乎不可见**。
   现场现象是"自检 2 秒内什么都不显示"，实测确认后改为**对 tick 翻转的 50% 占空方波**。

## 6. `disp_format` —— 数码管内容

纯组合。按状态决定 8 位数码管的 BCD 与熄灭掩码：

| 状态 | DISP7 | DISP6 | DISP5 | DISP4 | DISP3 | DISP2 | DISP1 | DISP0 |
|---|---|---|---|---|---|---|---|---|
| 自检 | 8 | 8 | 8 | 8 | 8 | 8 | 8 | 8 |
| 待机 | **5** | — | — | — | — | — | — | **关卡 1/2/3** |
| 预览 | **倒计时** | — | — | — | — | — | — | **关卡 1/2/3** |
| 拼图 | — | — | — | **十位** | **个位** | **2**※ | — | **关卡 1/2/3** |
| 胜利 | **P** | **A** | **S** | **S** | — | — | — | — |
| 失败 | **F** | **A** | **I** | **L** | — | — | — | — |

> **第三关（D2）在这些格子里的表现**：待机/预览/拼图的 DISP0 都显示 **3**（B3 的"关数由 DISP0 显示"；
> 第三关是 A2 扩展关，`disp_format` 的 `i_lvl3` 让它显示 3）；**DISP2 在第三关熄灭** ——
> B9 的 "DISP2 显示 2" 只属于第二关（实测 `o_blank`：第二关 `0xE2`、第一关与第三关同为 `0xE6`），
> 见 `tb_disp_format` ⑤⑥⑥b。

> ⚠️ **2026-10-09 改版（用户提问触发）**：结算画面原来只亮两位、显示**随意挑的记号 "75"/"00"**
> （唯一理由是"和其它状态都不重复"，**没有任何语义**）。用户问"通关后 DISP7、DISP6 显示 7、5
> 是什么意思"，遂改为**用最左四位拼字**：胜利 **`PASS`**、失败 **`FAIL`**，其余四位全灭。
> PDF 只规定 DISP0=关卡号（B3）、DISP7=预览倒计时（B4）、DISP4:DISP3=对局倒计时（B5）、
> DISP2='2'（B9），**对局结束后的数码管内容没有任何规定** → 自拟内容，能自解释更好。
> 详见 `docs/06` "结算画面数码管改版"小节。

**字位码约定**（`puzzle_pkg` §9，disp_format 的 `i_data` 半字节 = seg_scan 的译码输入）：
**`0x0`~`0x9` = 数字（BCD）、`0xA`~`0xE` = 字母、`0xF` = 灭**。
本设计用到的字母码：`DIG_A=0xA`、`DIG_P=0xB`、`DIG_S=0xC`、`DIG_F=0xD`、`DIG_L=0xE`、`DIG_I=0x1`。
实测：WIN → `o_data=0xBACC0000`、`o_blank=0x0F`；FAIL → `o_data=0xDA1E0000`、`o_blank=0x0F`。

> ⚠️ **7 段管的固有限制（如实写明，不是 bug）**：`'S'` 与 `'5'` 的段**完全相同**、
> `'I'` 只能用 `'1'` 的形状 → 板上 `PASS` 看着像 **PA55**、`FAIL` 像 **FA1L**。
> 结算时点阵上是**红色粗对勾 / 红色叉**，语境下判读不受影响。

※ 仅**第二关**显示（要求 B9 明文"DISP2 显示 2"；B3 明文"关数由 DISP0 显示"，**两者同时满足**，
见 `docs/00` §5 Q2；第三关题目没规定 → 自拟为灭，D2 实测）。

**十位/个位用查找表**而非 `/10`、`mod 10`——除法器是关键路径（见 §4.5 序 1）。

## 7. `seg_scan` / `dot_matrix_scan` —— 显示驱动

### 7.1 `seg_scan`

* 8 位共阴，段高有效、位选**低有效**；**1 kHz 扫描 → 每位 125 Hz 刷新**
  （顶层把它接 `tick_1k`）。⚠️ 2026-10-08 更正（**ERR-027**）：原来接 `tick_200` → 每位只有 **25 Hz**，
  低于 LED 临界闪烁融合（~60 Hz），上板"数码管闪得比较明显"；**占空比仍是 1/8，亮度不变**。
* **译码表新增 5 个字母段形**（2026-10-09，配合结算画面拼字 "PASS"/"FAIL"）：
  `0xA→A`（a b c e f g）、`0xB→P`（a b e f g）、`0xC→S`（a c d f g，**与 `5` 同形**）、
  `0xD→F`（a e f g）、`0xE→L`（d e f）；`0x1` 的数字 `1`（b c）**兼作字母 `I`**。
  **译码契约**从"0..9 之外一律灭"改成"**`0xF` 灭，`0xA`~`0xE` 是字母**"。
  ⚠️ `'S'≡'5'`、`'I'≡'1'` 是 7 段管的固有限制：板上分别是 **PA55 / FA1L**。
* **段位序**（手册原文，**本项目修过的一个真 bug**）：

```
seg(0)=AA→PIN_62   seg(1)=AB→59   seg(2)=AC→58   seg(3)=AD→57
seg(4)=AE→55       seg(5)=AF→53   seg(6)=AG→52   seg(7)=AP→51
```

> ⚠️ **历史 bug**：第一版把 AA 放在 bit7、AP 放在 bit0。
> 结果**逻辑上的 a 段物理上接到了小数点（PIN_51）**。
> 现场现象："显示 2 时少上面一横、小数点却亮了"。
> **波形上看不出来（RTL 自洽），只有上板才暴露** → 记入故障分析。

* 提供 `i_raw_en/i_raw` 诊断通道：**旁路译码器直接驱动段线**，
  这是"点亮指定单段"的唯一办法，用于逐段确认映射。

### 7.2 `dot_matrix_scan`

* 行**低有效**、列高有效；红绿两列同时为高 = 黄。
* **行序反转**（现场实测）：图 4-1 的左上角标记红点**出现在左下角**
  → `ROW0` 是**最下面**一行，故行译码按"从下往上"编号。
* 列序与红绿分组**实测正确**，不反转。

## 8. `rng_lfsr` / `buzzer_ctrl`

* **`rng_lfsr`**：8 位最大长度 LFSR（抽头 x⁸+x⁶+x⁵+x⁴+1），周期 255。
  **不接任何节拍**——只在 `i_step` 时推进。理由：自由运行的随机源无法复现、无法仿真，
  而要求 A3（位置随机）只需要"每关开始时"的随机性。
  复位强制非零初值（全零是吸收态，会永远停在同一点）。
* **`buzzer_ctrl`**：蜂鸣器不需要"音名"，只需要**分频比**与**持续时长**。
  ⭐ **当前（第 16 工作阶段）**：**4 位音效码 × 16 条 16 步（4 s）乐句**、**÷256 预分频**（**195312.5 Hz**）、
  **8 位**方波计数器；节拍 **`i_t4`（4 Hz，250 ms）**；`i_en=0`（SW7=0）时强制静音。
  三关 BGM = **马里奥 Overworld 开头 / Underground 开头 / Overworld 第二乐句**，
  **对局中移动 / 选择 / 开始键静音**（只留确认 `1100` 与旋转 `1010`）；`cnt >= half` 改成 **`cnt = half`** ——
  详见 **§15**。
  * **演进**：第 14 工作阶段 = ÷64 + 9 位计数器 + 8 步短语（音高 `C6..C7`，见 §13.1~§13.3）
    → 第 15 工作阶段只换内容（音高 `G5..C7`，仍 8 步，见 §14）
    → **第 16 工作阶段**换内容 + **乐句加长到 16 步** + **÷256** + **8 位计数器**（**§15**）。

## 9. 顶层与引脚

* **引脚绑定只出现在两处**：`rtl/puzzle_top.vhd` 的端口名 + `quartus/puzzle.qsf` 的
  `set_location_assignment`。引脚表由 `scripts/gen_project.py` **从手册转录并生成**，
  并有守卫："任一端口若在引脚表中查不到就报错退出"。
  > 这条守卫来自一次真事故：`btn` 漏配 → Quartus **不报错**，把该输入随机放到 PIN_50，
  > 表现是"复位键完全没反应"。见 `docs/05` §4。
* **不驱动 16 个 LED**：板上 `COLG0..COLG7`（点阵绿列）与 `LD8..LD15` **复用 PIN_38..45**，
  `PIN_137..144` 又与 VGA 复用。点 LED 就会丢掉点阵的绿色，
  而要求 B6（选中零片变绿）依赖绿色。题目 4 没有任何一条要求用 LED。

### 9.1 `puzzle_top` 的点阵内容多路器（**按状态决定颜色与图案**）

顶层一个组合进程按 `state` 直接给出红/绿两个平面的行内容（再交给 `dot_matrix_scan` 驱动）：

| 状态 | 红平面 | 绿平面 | 显示效果 | 依据 |
|---|---|---|---|---|
| `S_SELF_TEST` | `gblink` 全屏 | 同红 | **全黄**、2 Hz 方波闪 | B1 |
| `S_IDLE` | 全 0 | 全 0 | **全灭** | B2 |
| `S_PREVIEW` | `prev_row`（从 `tgt_mask` 切片） | 全 0 | 完整图案（**红**），5 秒 | B4 |
| `S_PLAYING` | 引擎帧 `eng_fr` | 引擎帧 `eng_fg` | 零片画面（选中=绿、锁定=黄、其余=红），**无目标虚影**（见 §4.4） | B5~B8 |
| `S_WIN` | 全 0 | `win_row & ev` | **绿色粗对勾**（24 格、3 格宽、填满整屏）——**只点绿列**（2026-10-09 用户拍板：绿对勾 / 红叉的"交通灯配色"） | B10 / S5 |
| `S_FAIL` | `fail_row & ev` | 全 0 | **红色叉**（与胜利构成反色对：绿=通过、红=不通过） | B9 / S5 |

**"先闪 2 个 2 Hz 周期再常亮"的实现（2026-10-08）**：结算画面（`S_WIN`/`S_FAIL`）共用
`endflash_cnt`（3 位）与 `endflash_on`：每来一个 `t_2hz` 脉冲加一，数到 3 就置 `endflash_on = '1'`，
亮度 `ev := gblink or endflash_on` —— 即 **4 个半周期（= 2 个 2 Hz 周期）内按 2 Hz 闪，之后常亮**；
离开 `S_WIN`/`S_FAIL` 立刻复位。自检（B1）**不使用 `ev`**，仍按需求无条件 2 Hz 闪烁。
（`win_row`/`fail_row` = 把 `WIN_MASK`/`FAIL_MASK` 按当前行号切出的 8 位。）

### 12.2 A4 旋转的几何实现（**本阶段最费心思的一处**）

**要求**：零片能原地顺时针转 90°，且**锚点不变**（锚点 = 零片**紧包围盒**的左上角）；
转出 8×8 或与别的零片重叠的请求**拒绝**。

| 写法 | 实测代价 | 结论 |
|---|---|---|
| ① 在紧包围盒里直接转 | **+229 LE**（1225 → 1454） | 装不下：每个下标都要 `h-1-c`/`w-1-c` + 范围保护，综合成"36 选 1" |
| ② 固定 3×3 盒里转（**不补偏移**） | 便宜 | ❌ **错**：紧包围盒 < 3×3 的零片会挪到盒子另一个角（1×3 横条落到第 2 列） |
| ③ **固定 3×3 盒里转 + 锚点偏移补偿** | **+64 LE** | ✅ **采用** |

③ 的做法：旋转本身仍然只在一行 3 位上做（`puzzle_pkg.rot_row`），偏移在**唯一一处**
算行掩码的地方补回来：

```
盒内行号 = (紧包围盒行号 sr) + dr         列移位 = (锚点列 ac) - dc
"00": (0,0)   "01": (0,3-h)   "10": (3-h,3-w)   "11": (3-w,0)
```

`srl8` 为此增加 `-1` / `-2` 两档负移位（语义不变：`v(j) = r(j-dc)`，越界补 0）。
`oh()`/`ow()` 给出旋转后的高宽（90°/270° 互换）。

**离线证明**（`scripts/check_geometry.py`）：用"在紧包围盒里直接转"当**独立参考模型**，
与 RTL 的"盒内转 + 偏移"**逐块 × 逐朝向 × 逐行**比对（7 块 × 4 朝向全部相等），并断言
每块原始/旋转后包围盒都锚在 (0,0)、高宽按朝向互换、任意朝向都塞得进 3×3、连转 4 次回原位、面积守恒。

### 12.3 旋转复用"移动校验流水"

一次旋转请求 = **同一个锚点 + 朝向 +1** 的候选，走与移动完全相同的四拍流水：

```
按钮(i_rot) → mv/mv_rot/mv_dir="0000" → 夹紧（不变） → 边界（用**旋转后**的高宽）
            → 重叠检查（chk_rot=1, chk_ori=ori+1） → 通过则提交 ori
```

* 边界：`cr + 旋转后高 ≤ 8` 且 `cc + 旋转后宽 ≤ 8`，否则**连检查都不启动**（等效拒绝）；
* 重叠：与移动同一套"一拍一个邻块"的串行检查，只是候选的形状换成旋转后的；
* **已锁定**的块 `locked(sel)='1'` → 判据里直接挡住（B8）。
* 提交时**只改 `ori`，`o_pos` 一个字都不动** —— 这是 A4 的核心不变量，整机断言 ⑰ 与模块旋转用例都在钉它。

### 12.4 重叠检查引擎：串行化 + 循环不变量外提

一拍只处理**一个邻块**，扫描顺序是"（候选自己的行 × 邻块槽）"：

```
对 chk_sr = 0..chk_srmax：  1 拍算候选本行(→chk_crow)  +  npc 拍逐个邻块比较
```

* 判定结果与"一拍并行比四个邻块"**逐条相同**（同集合的与非空判定）；
* 循环不变量 `chk_prowr = 候选锚点行 + chk_sr`（候选本行落在面板第几行）在载入 `chk_crow` 那一拍算一次，
  不再在每个邻块比较里重算 —— 这正是最后一条违例路径 `chk_slot → chk_hit` 的修法；
* ⚠️ **本模块只在渲染器上受 `i_tick` 门控**：移动/旋转/散落/检查引擎都跑 **`i_clk`**，
  所以一次检查是 **5~16 个 clk（100~320 ns）**，判决的真正延迟来自"整帧渲染"。

### 12.5 渲染器：串行化 + 准备/累加流水

一行 8 个面板行的帧，按 `ph` 相位推进（`npc` = 3 或 4）：

| ph | 动作 |
|---|---|
| 0 | **准备**第 0 块的行掩码（`bp`/`sp`/`op`） |
| 1..npc-1 | **累加**第 ph-1 块（`srl8 + 或门`），并**准备**第 ph 块 |
| npc | **累加**最后一块 |
| npc+1 | **发布**本行：`cov_a/kc_a/sl_a` → 红/绿 + 整帧判据 `bad` |

一行 `npc+2` 拍，一帧 40（一关）/ 48 拍（二、三关）；配合 `i_tick = 1 kHz` → **25 / 21 Hz 帧率**。
* 累加语义与旧版**逐位相同**（`cov/kc/selrow` 仍是四块零片的并集/锁定集/选中集）；
* "算掩码"与"并进累加器"被拆到相邻两拍 → 长链被切成两半（Fmax 47.54 → 49.49）；
* 第二拍（并入 frame + 整帧判据协议）沿用 ERR-033 的两拍流水，只在 `row_new='1'` 时动作。

### 12.6 干净帧判据与 `pos_cnt`

`frm_valid` 要求"上一整帧里 pos/level/pat 没变过"。第 13 工作阶段把 **32 位 `pos_frm` 快照**
换成 **4 位提交计数器 `pos_cnt`**（每次提交 `pos`/`ori` 时 +1，帧头快照 `p_frm`）—— **−38 LE**；
别名需要"一帧里提交 ≥16 次"，而每次提交都要跑完一次 ≥5 clk 的重叠检查且检查被引擎串行化，
48 拍的一帧最多 8 次 → **不可能**。

⚠️ 另有一条**已记录未修**的窗口问题（**ERR-041**，由 `tb_puzzle_ctrl` 的扫描不变量抓出）：
快照在帧头拍，而第 0 行在这之前 `npc+1` 拍就算完了 —— 那一小段里的变化拍不到。
**可达性论证表明本设计到不了这个窗口**（只有 `pos` 变化才会混帧，而 `pos` 只在 CH_DONE 提交，
且提交的前提是"该块未锁定/正在散落"，也就是**全锁时不可能发生**；而 FSM 的胜负分支都要全锁），
修法的实测代价是 **1266 LE / Fmax 48.83 MHz**（把刚达标的 50 MHz 还回去）且其他 seed 装不进，
所以**记录在案、不改**（见 `docs/06` §14、`HANDOFF.md` §4）。

### 12.7 A1 旋律播放器（`buzzer_ctrl`）

> ⚠️ **本小节是第 13 工作阶段的版本，已被 §13.1~§13.3 的"A1 v2"取代**（8 音高 G4..C6 → 4 位码 /
> 16 短语 / C6..C7；对局期间不再静音；瞬时码保持 2 步）。保留作演进记录。

* **8 个音高**（G4 392 / A4 440 / B4 494 / C5 523 / D5 587 / E5 659 / G5 784 / C6 1047 Hz），
  半周期 = `25e6 / f`（全部 < 65536 → **16 位**计数器）；
* **8 步乐句**，每步 4 位常量 = `bit3` 响不响 + `bits2..0` 音高；节拍 = **`i_t4`（4 Hz，250 ms）**，
  一句 2 s 循环；
* 四个状态保持的场景**完整成句**：`001 自检`（上行号角）、`010 预览`（两短声）、
  `110 胜利`（C5 E5 G5 C6 G5 C6 C6）、`111 失败`（下行三音）；
* ⚠️ **已知不足**：`011/100/101` 三个码在 `game_fsm` 里只有 1 个 clk，而旋律需要码保持 ≥1 步 →
  实际只发出 ~20 ns 毛刺（**旧版同样听不见**）；修法（2 位保持计数器 ≈13 LE）因余量只剩 10 LE 未做。

### 12.8 `clk_gen` 的两处优化

1. **按键消抖**：20 位移位寄存器 + 20 输入与门 → **5 位饱和计数器** + 5 位比较。
   语义逐条对齐（tb 断言 ⑥⑦⑧⑩ 实测：连满 20 个 1 ms 样本才置位、任一低样本立刻清零、
   8 样本毛刺不产生复位），并且**复位网络**（原来全设计的最差路径源头）短了两级。
2. **4/2/1 Hz 合并成一条链**：原 c4（÷50）/c5（÷100）/c7（÷25）三套计数器共 18 个触发器 →
   一个 ÷25 计数器 + 2 位"第几个 4 Hz"共 7 个（周期比与相位关系由 tb 断言 ②③ 复核）。
   `clk_gen` **118 → 74 cells**。

### 13.1 A1 v2：音效码从 3 位扩到 **4 位**，短语从 8 个扩到 **16 个**

**为什么扩**：3 位码最多 8 个场景，而"不同情况播放不同音效"（A1 原文）在**有背景音乐**之后
至少需要区分：静音 / 自检 / 预览 / 过关 / 拼错 / 按键 / 胜利 / 失败 / **背景音乐** / 旋转 / 确认 /
选择 / 移动 / 被拒 / 末 5 秒 / 备用 = **16 个**。所以 `puzzle_pkg` 新增 4 位码：

| 码 | 常量 | 场景 | 短语（8 步，`-` = 休止） |
|---|---|---|---|
| `0000` | `SND_NONE` | 静音（待机） | `- - - - - - - -` |

**为什么"瞬时事件"的短语全部无休止符**：旋律步进计数器是**自由跑**的（不因换码而复位），
一个瞬时事件可能落在**任意一步**上。若短语里有休止符，事件就有概率落在休止步上 → **听得见是概率事件**。
所以九个瞬时短语（`0011/0100/0101/1001/1010/1011/1100/1101/1110`）**每一步都有音**。

> ⚠️ **本段的码值与个数是第 13 工作阶段的历史记录**（3 位码时代，9 个短语）。
> **当前（第 16 工作阶段起）只有 5 个"事件码"**：`0011/0100/0101/1010/1100`
> —— `1101/1110/1111` 的查表分支已删（落入 `when others` ⇒ 静音），码值映射也已换成 §15 的表。
> "**事件码短语必须全发声**"这条**规则仍然有效**（§15.3 / §16.2）。
**状态保持类**的短语（`0001` 自检 / `0010` 预览 / `0110` 胜利 / `0111` 失败 / `1000` 背景音乐 / `1111` 备用）
**保留休止符** —— 它们要持续数秒，一句 2 s 循环，休止符是乐句的一部分。

### 13.2 音高表与 **÷64 预分频**

音高带整体上移到 **C6..C7**（板上小蜂鸣器在 1~2 kHz 附近最响）：

| 下标 | 音名 | 目标频率 | 半周期（tick 数） | **真实器件频率** | 误差 |
|---|---|---|---|---|---|
| 0 | C6 | 1046.5 Hz | 373 | **1044.5 Hz** | −0.20% |
| 1 | D6 | 1174.7 Hz | 333 | **1169.5 Hz** | −0.44% |
| 2 | E6 | 1318.5 Hz | 296 | **1315.2 Hz** | −0.25% |
| 3 | F6 | 1396.9 Hz | 280 | **1390.1 Hz** | −0.49% |
| 4 | G6 | 1568.0 Hz | 249 | **1562.5 Hz** | −0.35% |
| 5 | A6 | 1760.0 Hz | 222 | **1751.7 Hz** | −0.47% |
| 6 | B6 | 1975.5 Hz | 198 | **1962.9 Hz** | −0.64% |
| 7 | C7 | 2093.0 Hz | 187 | **2077.8 Hz** | −0.73% |

* 半周期 = `round(25e6 / (64 × f))`；**÷64 预分频**把方波计数器的输入从 50 MHz 降到
  **781.25 kHz**（一拍 1.28 µs）→ 计数器从 **16 位缩到 9 位**（振荡器侧 **63 → 49 cells**）。
* 代价与取舍（**实测**）：4 位码 + 16 短语的查表在 4 输入 LUT 上是 **+17 cells**（128×4 ROM 的
  固有开销）；**扁平 ROM / 二维数组两种写法实测都更差**。`buzzer_ctrl` 整机层次表
  **68 → 57 logic cells**。
  ⚠️ **孤立单模块流会给出相反结论（81 → 84，变贵）** —— 跨模块 `AUTO_RESOURCE_SHARING`
  只在整机里生效。**报面积一律用整机口径**（`docs/05` §1.1 的同一张表）。

### 13.3 保持机制：`snd_hold` + **刻意不留独立锁存寄存器**

两个子问题：

1. **对局期间不能静音**：`S_PLAYING` 的默认码从 `"000"`（静音）改成 **`SND_BGM`**；
   末 5 秒由 `game_fsm` 每秒发一次 **`SND_TIME`** 覆盖它。
2. **瞬时码要保持 ≥1 个旋律步**（250 ms）：新增 **2 位 `snd_hold`** 计数器 —— 任何**瞬时事件**
   （过关/拼错/按键/选择/确认/旋转/移动）把码推上总线时置 `snd_hold = "10"`，
   每个 `i_t4`（250 ms）减一，期间**默认码不得覆盖它**。
   → 保持窗口 **250~500 ms**，`tb_game_fsm` ㉔ 逐拍实测。

**为什么不同时加一个 4 位锁存寄存器**（最直观的写法）：`sound_p` 在 `snd_hold /= 0` 期间
**本来就保持住自己的值**（它是有条件的赋值，不是无条件跟随计算值）→ 再加锁存纯属重复。
实测 **1297 → 1290 LE**（省 4 个 FF + 一个 4 位 mux）。

**键位译码集中成一处**：`game_fsm` 用**一个 `case kdec`** 把键码映射到音效码
（确认→`SND_CONF`、旋转→`SND_ROT`、选择→`SND_SEL`、方向→`SND_MOVE`、其它→`SND_KEY`）。

### 13.4 `PIECE_ORI_INIT`：把"旋转"从可选变成必需

```vhdl
-- rtl/puzzle_pkg.vhd
constant PIECE_ORI_INIT : std_logic_vector(7 downto 0) := "10" & "10" & "01" & "01";
```

| 项 | 内容 |
|---|---|
| 语义 | 四块零片各 2 位朝向（块 k = `ori(2k+1 downto 2k)`），初始值 **1 / 1 / 2 / 2**（`"01"`=顺 90°、`"10"`=180°） |
| 装载点 | `puzzle_ctrl` 的**复位**与 **`i_go`（散落）**（原来写 `(others => '0')`）→ 每局开局都是这组朝向 |
| 为什么这样就"必需" | 四幅目标图案是用**只许平移**的铺法搜索推导的；开局朝向非零后，"一次都不转"的路线**不再存在** ⇒ 玩家**必须**至少转一次（实际上每块都要转） |
| 代价 | **0 LE**：常量换常量；同一份向量对**第一关与二/三关都成立**，不需要按关卡选 mux |
| 证明① | `scripts/check_geometry.py` 新增 **"A4 旋转必需性"**：对第一关 4×3 与 PAT0..PAT3 穷举"保持初始朝向 + 只许平移"→ **无一有精确覆盖**；允许旋转后**都仍可解**；四块在初始朝向下**形状真的变了（4/4）** |
| 证明② | 四份走法计划（`sim/tb_puzzle_top.py`、`scripts/check_plans.py`）**不是"给老计划加旋转前缀"，而是由带旋转的 A\* 从零重新解出**：状态 = (锚点, 朝向, sel)，动作 = 移动 / 旋转 / 换零片，代价 = **按键次数**（换零片要按 `(k'-k) mod n` 次【选择】），起点 = 确定性回退锚点 `(0,0)/(0,4)/(4,0)/(4,4)` + 出厂朝向 `PIECE_ORI_INIT = (1,1,2,2)`，终点 = 精确铺法，取按键最少者。结果：一关 **19 条命令**（2 `rot`、末锚点 `(2,2)(3,2)(3,2)`、末朝向 `(2,2,2)`，下界 16 ⇒ **可证最优**）；二关 PAT3 **34 条命令**（2 `rot`、`(5,3)(2,1)(2,2)(2,3)`、朝向 `(2,2,2,2)`；唯一的另一种铺法下界 29，且已证明**没有 ≤29 的解** ⇒ 34 最优）；三关 PAT0 **24 条命令**（2 `rot`、`(2,2)(2,5)(3,2)(3,3)`、朝向全 2）；三关 PAT2 **30 条命令**（7 `rot`、`(2,1)(4,4)(3,1)(2,4)`、朝向 `(2,2,1,0)`）。四份都在忠实的 Python 引擎模型里重放：**0 次被拒、全部锁定、并集 == 目标图案**；**把每一条 `rot` 删掉就无解**（反向守卫） |
| 计划里的常量从哪来 | `scripts/check_plans.py` **从 `rtl/puzzle_pkg.vhd` 现读 `PIECE_ORI_INIT`**（不硬编码），并在 `play()` / `union_of()` 里建模旋转；期望值显式写成 `L1_EXPECT_POS = 0x22323200`、`L2_EXPECT_POS = 0x53212223`、`L3_EXPECT_POS = {0: 0x22253233, 2: 0x21443124}` 与 `L1_EXPECT_ORI = (2,2,2)`、`L2_EXPECT_ORI = (2,2,2,2)`、`L3_EXPECT_ORI = {0: (2,2,2,2), 2: (2,2,1,0)}`，并做**朝向感知**的可达性抽样 |
| 测试前提 | `sim/tb_puzzle_ctrl.py` **不给 RTL 打任何补丁**（`RTL_PATCHES` 在那里**没有使用**）：它按新初态**重新推导**散落起点锚点与目标朝向，直接跑在仓库真正的 `rtl/` 上、用**出厂的 `PIECE_ORI_INIT`**；实测 **r26 = 27/27**（激励 **2 830 700 ns**、"**RTL 补丁：无**"）。旧版"把它钉回 0 以保住老计划"的做法**已废弃**（等于把真实初态从覆盖里删掉，且补丁一旦漂移就变成 ERR-022 的"陈旧绿"） |

| `1110` | `SND_MOVE` | 移动一步 | `G5 ×8` | 瞬时 |
| `1111` | `SND_TIME` | **预留**（原"最后 5 秒催促"，本轮为装箱删掉生成） | `C6 G5 C6 G5 C6 G5 C6 G5` | 瞬时 |

> ⚠️ **口径**：上表的码值取自 `rtl/puzzle_pkg.vhd` 的 `SND_*` **常量定义**，
> 并经 `rtl/buzzer_ctrl.vhd` 的 `case i_sel` 与 `sim/tb_buzzer_ctrl.py` 的 `MEL` 表**三方交叉核对**。
> ⚠️ **但 `rtl/puzzle_pkg.vhd` / `rtl/buzzer_ctrl.vhd` 里仍留着上一版的码位注释**
> （"`SND_ROT` 挪到 `1101`、选择与移动共用 `1110`"、"`sound_p <= "100" & lvl3 & level`"），
> 与常量定义和 `game_fsm` 的实际赋值**不一致** ——
> **以"常量 + `game_fsm` 赋值 + tb 断言"三方一致的行为为准**（见 `docs/06` §16.1 的差异留档），
> 那几行注释**待下一轮按实现重写**。

**"瞬时 / 常驻"的分类决定了乐句要不要留休止符**（第 14 工作阶段的结论，本轮沿用并细化）：

* **瞬时事件**（`0011/0100/0101/1010/1100/1101/1110/1111`）：码只保持 **2 个旋律步**
  （`game_fsm.snd_hold`），而步进计数器**自由走**（换码不清零）→ 事件可能落在**任意一步**上，
  所以**8 步必须全部发声**（否则"按了没反应"会变成概率事件）。
* **常驻场景**（`0001/0010/0110/0111/1000/1001/1011`）：会被保持数秒、一句 2 s 循环，
  休止符是**乐句的一部分**（例如胜利句第 4 步留白，是为了让顶点长音"站住"）。

### 14.2 三首背景曲：**级数推导**（为什么移调后仍在这 8 个音里）

三首**全部是公有领域**（两首古典 + 一首俄罗斯民歌），且**都能整句移调到同一个 8 音集合**（§14.5）：

| 关卡 | 曲子 | 原调动机 | 级数（相对主音） | 本设计移调到 | 落地乐句 |
|---|---|---|---|---|---|
| 第一关 | **Korobeiniki**（俄罗斯方块 A 主题） | A 小调 `E B C D C B A A` | `5 2 ♭3 4 ♭3 2 1 1` | **G 小调**（主音 A→G） | `D6 A5 A#5 C6 A#5 A5 G5 G5` |
| 第二关 | **欢乐颂**（贝多芬第九） | C 大调 `E E F G G F E D` | `3 3 4 5 5 4 3 2` | **G 大调**（主音 C→G） | `B5 B5 C6 D6 D6 C6 B5 A5` |
| 第三关 | **命运交响曲开头动机**（贝多芬第五） | C 小调 `G G G E♭ F F F D` | `5 5 5 ♭3 4 4 4 2` | **G 小调**（主音 C→G） | `D6 D6 D6 A#5 C6 C6 C6 A5` |

* **级数逐音不变、只换主音** —— 所以三首曲子听起来仍是原曲（不是"改了调的原创"）。
* **为什么都往 G 靠**：主音落在 **G** 上，第一/第三关的 G 小调级数
  {1, 2, ♭3, 4, 5} → {G5, A5, A#5, C6, D6}，第二关的 G 大调级数 {2, 3, 4, 5} → {A5, B5, C6, D6}，
  再加高八度主音 **G6** 与顶端 **C7**（按键/旋转用）—— **恰好 8 个音**。
* ⚠️ **第三关选"命运"是内容考虑**：它是"敲门"式的紧张动机，适合最后一关；
  同时它的级数（5 5 5 ♭3 4 4 4 2）与第一关**完全不同**，两关**不会听混**。

### 14.3 自检 = **POST 单声短鸣**（行业惯例）

| 项 | 内容 |
|---|---|
| 惯例 | **PC / 工控设备的 POST（Power-On Self-Test）蜂鸣器代码**：**"一短声 = 自检通过"**，多短声/长声才是报错 |
| 实现 | 自检短语 = **1 声响（C6，index 4，半周期 373 拍 ≈ 1046 Hz）+ 7 步留白** |
| 为什么恰好一声 | 一句 = 8 步 × 250 ms = **2 s**，而 `S_SELF_TEST` 也正好持续 **2 s**（B1）→ 整段自检**恰好响一声**，不会循环出第二声。⚠️ **第 16 工作阶段第二轮起乐句变成 16 步、发声步是第 0/8 步**，且**这个"恰好一声"只在复位/上电路径成立**（`i_rst` 同时清零 `step` 与 FSM）—— **SW7 关→开重新进入时 `step` 自由走，可能整段不响**，详见 **§16.1 / ERR-051** |
| 与旧版对比 | 旧版 = `C6 E6 G6 C7` **四声上行号角**：那是"开机/启动"语汇，**不是"自检结论"** |

### 14.4 胜负音效：**行业惯例 → 可执行的乐句参数**

| 场景 | 惯例 | 本设计 | 怎么体现惯例 |
|---|---|---|---|
| **过关**（`0011`） | 主和弦上行琶音 | `G5 B5 D6 G6` ×2 | 纯上行琶音 = "通过/得分"；**不拖长**，与胜利号角同族但**听得出区别** |
| **通关胜利**（`0110`） | 上行琶音 **+ 顶点长音**（"ta-da"） | `G5 B5 D6 G6 - G6 G6 G6` | 琶音给"上行"，**G6 连停三步**给"结束"；第 4 步留白是让顶点**站住**而不是滑过去 |
| **失败 / Game Over**（`0111`） | **下行**，**结尾落在最低音并拖长**（资料来源原话：Game Over 音乐"markedly slower and ends with a slight ritardando"） | `C6 A#5 A5 G5 G5 - G5 G5` | 半音下行到最低音，**最后三步都在最低音 G5** —— 用"更长的低音结尾"扮演渐慢 |

> ⚠️ **做不到的部分如实写明**：旋律步长是**固定的 250 ms 网格**（`i_t4` 接 `tick_4hz`），
> **做不出真正的 ritardando（渐慢）**。本设计用"**更长的低音结尾**"近似这一半语义，
> 而**不是**声称实现了速度变化。

### 14.5 8 个音高（**3 位索引不变**）与"为什么 G5 是地板"

| 下标 | 音名 | 目标频率 | 半周期（预分频 tick） | 真实频率 | 误差 |
|---|---|---|---|---|---|
| 0 | **G5** | 784.0 Hz | **498** | 784.1 Hz | +0.01% |
| 1 | A5 | 880.0 Hz | 444 | 879.7 Hz | −0.03% |
| 2 | A#5 | 932.3 Hz | 419 | 932.1 Hz | −0.02% |
| 3 | B5 | 987.8 Hz | 395 | 988.9 Hz | +0.11% |
| 4 | **C6**（POST 自检声） | 1046.5 Hz | **373** | 1046.9 Hz | +0.04% |
| 5 | D6 | 1174.7 Hz | 333 | 1173.1 Hz | −0.13% |
| 6 | G6 | 1568.0 Hz | 249 | 1568.8 Hz | +0.05% |
| 7 | C7 | 2093.0 Hz | 187 | 2088.9 Hz | −0.20% |

* 半周期 = `round(390625 / f)` 拍（`50 MHz / 64 = 781.25 kHz` 预分频后的 tick），
  **最大 498 < 512 ⇒ 方波计数器仍只要 9 位**。
* **为什么最低音是 G5、不是 F5**：**498 拍刚好装进现有的 9 位计数器（上限 511）**；
  **F5 需要 561 拍 ⇒ 要 10 位计数器（+2 LE）**。这是**实测边界**。
* **为什么不需要 16 个音（4 位索引）**：三首曲子 + 胜利琶音 + 旋转音阶
  **全部落在这 8 个音里**（§14.2）。⭐ **16 音方案真做过也真量过：+3 LE，
  在只剩 2 LE 余量的器件上装不下 → 否决**（负结果见 `docs/05` §1.4）。
* 与第 14 工作阶段的 C6..C7 音高表相比：**表长、位宽、预分频都没变**，
  只是**换了 8 个音**（从"C 大调段"换成"G 小调/G 大调和声骨架"）——
  这正是"内容升级不花面积"的关键。

### 15.2 三首背景曲与四个语汇：原谱 → 本设计（**级数与节奏逐音不变**）

| 用途 | 码 | 曲子 / 语汇 | 原谱（C 大调记谱） | 本设计（整体移调进 `E5..G6`） |
|---|---|---|---|---|
| 第一关 BGM | `1000` | **Super Mario Bros "Overworld" 主题开头** | `E5 E5 - E5 - C5 E5 - \| G5 - - - G4 - - -` | `E6 E6 - E6 - C6 E6 - \| G6 - - - G5 - - -` |
| 第二关 BGM | `1001` | **Super Mario Bros "Underground"（地下关）开头** | `C5 C5 A4 A4 A#4 A#4` | `C6 C6 A5 A5 A#5 A#5`（留白后重复） |
| 第三关 BGM | `1011` | **Overworld 主题第二乐句** | `C5 - - G4 - - E4 - \| - A4 - B4 - A#4 A4 -` | `C6 - - G5 - - E5 - \| - A5 - B5 - A#5 A5 -` |
| 预览 / 倒计时 | `0010` | **马里奥"金币"音效** | `B5 → E6`（上行四度） | 一循环响两次（第 0/1 步与第 8/9 步） |
| 通关胜利 | `0110` | **过关号角（Course Clear）写法** | 上行大三和弦琶音 ×2 + 下行收束 | `C6 E6 G6 -` ×2 + `G6 E6 C6 C6`（**主音拖长**） |
| 失败 | `0111` | **Game Over 写法** | 三声下行 + 下行小尾句 | `C6 G5 E5 -` + `A5 B5 A5 A#5 G5 E5 A5 G5 E5`（**停在最低音**） |
| 自检 | `0001` | **行业标准的 POST 单声短鸣** | 一声 ≈1 kHz | `C6`，放在**第 0 步与第 8 步** |

* **为什么第一关与第三关是同一个主题的两半**：Overworld 的**第一乐句给第一关、第二乐句给第三关**
  —— 既满足"三关三首、逐关听得出换曲"，又让第三关听起来"还是马里奥、但是另一句"。
* **为什么第二关选 Underground**：它的动机（三组同音 + 留白）与第一关的**节奏型完全不同**，不会听混。
* **为什么这三首正好装进 8 个音**：三首曲子所需音级（自然音级 + 一个 `A#5` 的变化音）合起来
  只用到 **E5/G5/A5/A#5/B5/C6/E6/G6** 这 8 个音 —— **音高索引仍是 3 位**（§15.4）。
* ⚠️ **Game Over 的"渐慢"仍然做不到**（固定 250 ms 网格）：本轮改用**"下行小尾句 + 停在最低音"**
  表达"塌下来/结束"的听感，**不声称实现了 ritardando**（与 §14.4 同一条如实记录）。

### 15.3 按键取舍：对局中**只留两个**反馈音（ERR-047）

### 15.4 面积：16 步乐句把查表推到 **8 输入**（ERR-049）

**① 新的 8 个音（3 位索引不变）与 ÷256 预分频**

| 下标 | 音名 | 目标频率 | 半周期（tick） | 真实设计频率 | 偏差 |
|---|---|---|---|---|---|
| 0 | **E5** | 659.3 Hz | **148** | 655.4 Hz | −0.59% |
| 1 | G5 | 784.0 Hz | 125 | 775.0 Hz | −1.14% |
| 2 | A5 | 880.0 Hz | 111 | 871.9 Hz | −0.92% |
| 3 | A#5 | 932.3 Hz | 105 | 921.3 Hz | −1.18% |
| 4 | B5 | 987.8 Hz | 99 | 976.6 Hz | −1.14% |
| 5 | C6（POST 自检声） | 1046.5 Hz | 93 | 1038.9 Hz | −0.73% |
| 6 | E6 | 1318.5 Hz | 74 | 1302.1 Hz | −1.25% |
| 7 | G6 | 1568.0 Hz | 62 | 1548.9 Hz | −1.22% |

* 时间基准：`50 MHz / 256 = 195312.5 Hz`（`PRE_DIV = 256`），`f = 195312.5 / (2 × (half+1))`。
* **最大半周期 148 拍 < 256 ⇒ 计数器只要 8 位**（原来 ÷64 时是 498 拍、要 9 位）——
  这就换来 **−2 LE**（计数器 + `half` 多路器 + 相等比较器各少 1 位）。
* ⚠️ **音准**：tick 变粗后取整误差让**整首曲子统一偏低最多 ≈1.2%（≈1/6 个半音）**；
  但**音程关系保留在 ~0.5% 内**，所以"听得出是哪首"完全不受影响 —— 这是**明确接受的音质↔面积取舍**。

**② 为什么 16 步会多花 ~4 LE**

| 项 | 8 步（旧） | 16 步（新） |
|---|---|---|
| 查表输入 | 码 4 位 + 步 **3 位** = **7 输入** | 码 4 位 + 步 **4 位** = **8 输入** |
| 每个输出位要几个 LUT4 | **2 个** | **3 个**（8 输入要两级 LUT4 才能覆盖） |
| 输出位 | `tone_sel` 3 位 + `on_now` 1 位 = 4 位 | 同 4 位 |
| 旋律表合计 | 4 × 2 = 8 个 LUT | 4 × 3 = **12 个 LUT** ⇒ **+4 LE** |

* ⚠️ **这就是"加长乐句"的真正代价**：`step` 只多 1 位，但**跨过了 4 输入 LUT 的边界**，
  面积是**跳档**而不是线性增长。负结果留档见 `docs/05` §1A/§1.4。
* ⚠️ **`buzzer_ctrl` 表头注释里写的是"8 位也只要 2 个 LUT4/输出位"** —— 与实测不符。
  ✅ **第 16 工作阶段第二轮已把这处注释按实测改正**（现在写的是"**8 位函数每输出位 3 个 LUT4**"），
  **不再是待办**；同理，方波发生器那句"`cnt = half` 要等 **511** tick"也已改成 **255 tick（≈1.31 ms）**
  （见 §15.7 ⑥ 与 `docs/06` §17.4）。

**③ 省回面积的四步 + seed 重扫**

| 步 | 改动 | 效果 |
|---|---|---|
| ① | 预分频 ÷64 → **÷256** + 半周期计数器 **9 → 8 位** | **−2 LE** |
| ② | 删掉 `1101/1110/1111` 三个不再生成的 `case` 臂 | 查表更小 |
| ③ | `cnt >= half` → **`cnt = half`**（等价：`cnt` 从 0 逐 1 加到 `half` 必然相等） | 相等比较比"大于等于"的进位链便宜 |
| ④ | 删掉 `game_fsm` 上**从未使用**的 `i_tick_2hz` 死端口（`puzzle_top` 同步） | 少一根端口/网 |
| ⑤ | **重扫 fitter `SEED` 1~16** | ⭐ **本版只有 seed 9 / 11 装进 127 LAB**（**11 时序最好 52.7 MHz**，9 = 51.3；1/3/5/7/8 要 **128 LAB**）→ `gen_project.py` 固定 **`SEED 11`** |
| ⑥ | **清洁重编译**后 `quartus_sta` | **1269 / 1270 LE（100%）、LAB 127/127、setup slack +1.024 ns、hold +1.078 ns** |

**④ `cnt = half` 的如实记录的副作用**：当**换到更低的音**时，新的 `half` 可能小于当前 `cnt`，
这一轮要等 `cnt` 走满 **255 个 tick（≈1.31 ms）**回绕才对齐 —— 即该步多出一个"超长半周期"。
**听不出来**，仿真也确认没有异常间隔。这是"用相等比较省面积"换来的一处可接受的瑕疵。

### 15.7 连奏填音（第二轮，2026-10-09 23:4x，ERR-050）—— ⭐ **发声步以本表为准**

> **起因**：用户在第一轮固件烧上去之后紧接着反馈
> "**目前蜂鸣器的音乐不够连贯，现在断断续续的效果不好**"。
> **根因**：第一轮的转录是**逐音照抄原谱、连休止一起抄** ——
> 超级马里奥 Overworld 开头一句 **16 步里只有 7 步真正发声（56% 的乐句是静音）**，
> 而每步 **250 ms**，所以听起来就是 `嘀` … 停 … `嘀` … 停。
> ⚠️ **旋律本身没有错，坏的是占空比（duty cycle）/ 连奏** ——
> **"转录正确"不等于"单音蜂鸣器上听得好"**。

**① 修法：连奏填音（legato fill）—— 只改常量表，不改逻辑**

* 规则：**每个休止步填成"下一个将要发声的音高"**；**句尾的休止填"上一个音"**。
* ⇒ **音高序列与音的先后顺序一个都没变**（还是那几首能听出来的曲子），但 **16 步全部发声**，
  变成**一条连绵的旋律线**；`mel_t` 结构、8 音 / 3 位索引、`step` 计数**全都不动**。

**② 前/后占空比与逐句对照**

### 16.1 ⭐ 自检单声的适用前提（**ERR-051**）—— "与相位无关"是过强的说法

| 进入路径 | `step` 计数器的状态 | 自检窗口（≈2 s = 8 个旋律步）覆盖到的发声步 | 听感 |
|---|---|---|---|
| **复位 / 上电** | `i_rst` **同时清零 `step` 与 FSM** ⇒ 必从 **第 0 步**开始 | 第 **0** 步（发声步 = **0 与 8**） | ✅ **恰好一声**（POST 语义真正要求的路径） |
| **SW7 关→开重新进入** | **不复位**，`step` **自由走** | 取决于进入相位：**有些相位一个发声步都碰不到**（另有些只能覆盖半声） | ⚠️ **可能整段不响**，也可能只有半声 |

* **根因**：`buzzer_ctrl` 的 `step` 是**自由走**的（4 位、mod 16，换码与换状态都不清零 —— 这条本身是
  第 14 工作阶段为"瞬时事件"刻意保留的语义），而 `MEL_SELF` 只在**第 0 与第 8 步**发声；
  自检状态又只持续 **2 s（8 步）** ⇒ **窗口与发声步是否重叠取决于进入相位**。
* **影响**：**低** —— 重启时少一声 chirp，**不影响任何功能**（点阵闪烁、8 位数码管、后续流程都正常）。
* **已做的修**：改正 `rtl/buzzer_ctrl.vhd` 里那句"无论从哪一步进来都恰好一声"的注释，
  并在 `HANDOFF.md` 未决项里写明**两条修法与代价**：

| 方案 | 做法 | 代价 | 结果 |
|---|---|---|---|
| **(a) 推荐** | 进入 `S_SELF_TEST` 时**清零 `step`** | **≈2~3 LE**（99% 占用率下需先确认装得下）+ **必须放宽 `tb_buzzer_ctrl` 断言 ⑯**（它现在专门钉"进状态不清零 `step`"） | **两条路径都恰好一声** |
| (b) | 把 `MEL_SELF` 的发声步改成 **0/4/8/12** | **0 LE** | 任何 2 s 窗口至少覆盖 1 个发声步，但**复位路径变成 1~2 声**（POST 语义变弱） |

* **会话结束时为什么没做 (a)**：要同步改测试台（属"改判据"而不是"改注释"），而收益只有一声 chirp
  —— **收益不抵回归风险**，留给下一轮（`HANDOFF.md` 未决项第 3 条）。
* ⚠️ **任何地方都不要再写"自检声与相位无关 / 无论从哪一步进都恰好一声"**。
* ✅ **不受影响的部分**：`MEL_SELF` 的**内容**（C6 ≈1 kHz、第 0/8 步各一声）、tb 断言 ② 的逐句比对、
  `docs/03` 的 `buzzer_ctrl` 16/16 —— **都没有变**，变的只是**对适用范围的描述**。
